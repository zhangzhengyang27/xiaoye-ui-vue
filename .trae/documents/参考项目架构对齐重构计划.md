# 参考项目架构对齐重构计划

## 摘要

将当前扁平单包项目（ant-design-vue-main，包名 `xiaoye-ui@4.2.6`）重构为对齐参考项目 `xiaoye-ui-vue` 的 pnpm monorepo 架构。包含：9 个子包垂直拆分、Vite 库模式 + ESM-only 构建链、入口与 exports 自动生成、文档站迁移到 Nuxt、共享层重构、工程化治理。

**决策信息**（来自用户确认）：
- monorepo 拆分粒度：完整对齐参考项目（8+ 包）
- 构建产物策略：ESM-only（不产 CJS/UMD）
- 文档站：迁移到 Nuxt

---

## ESM-only 影响说明

选择 ESM-only 会放弃两类用户，需在计划中明确知悉：

1. **CJS 用户**：用 `require('xiaoye-ui')` 的 Node.js CommonJS 项目会报错（`ERR_REQUIRE_ESM`）。但 Vue 3 生态已全面 ESM 化，现代打包工具（Vite/webpack5/Rollup/esbuild）均原生支持 ESM，实际影响面小。
2. **UMD/直接 `<script>` 引入用户**：无法用 `<script src="https://unpkg.com/xiaoye-ui"></script>` 直接引入。替代方案：使用 `esm.sh`（`https://esm.sh/xiaoye-ui`）或 jsdelivr 的 ESM 模式（`https://cdn.jsdelivr.net/npm/xiaoye-ui/+esm`）。

**应对**：在 package.json 保留 `unpkg`/`jsdelivr` 字段指向 ESM 产物，并在 README/AGENTS.md 中说明 CDN 引入方式变更。

### 阶段 4：入口与 exports 自动生成（中风险）

**目的**：消除手工维护 `components.ts` 和 `global.d.ts` 的漂移风险。

**任务清单**：

1. **prebuild 脚本**（`packages/xiaoye-ui/scripts/prebuild.mjs`）

   - 生成 `src/index.js`：
     ```js
     // Auto-Generated - DO NOT EDIT
     export * from 'xiaoye-ui/button';
     export { default as Button } from 'xiaoye-ui/button';
     export * from 'xiaoye-ui/button/style';
     // ...所有组件
     ```
   - 生成 `src/index.d.ts`（类型聚合）
   - 生成 `package.json > exports`（每个组件 `./<name>` + `./<name>/style` 双入口）
   - 生成 `vetur/web-types.json`、`vetur/vetur-tags.json`（复用 `generator-types/`）
   - 生成 `typings/global.d.ts`（从组件清单派生，消除漂移）

2. **postbuild 脚本**（`packages/xiaoye-ui/scripts/postbuild.mjs`）
   - 调用 `build-helper.mjs` 的 `applyPublishConfig`：把 package.json 的 `main`/`module`/`types`/`exports` 从指向 `src/` 重写为指向 `dist/`
   - 调用 `normalizeWorkspaceDependencies`：把 `workspace:*` 转成 `^x.y.z`
   - 复制 `.d.ts` 文件、清理临时字段

3. **package.json 双态设计**
   - 开发期（主体）：`"main": "./src/index.js"`、`"exports": { ".": "./src/index.js", "./<name>": "./src/<name>/..." }`
   - 发布期（`publishConfig`）：`"main": "./index.mjs"`、`"exports": { ".": "./index.mjs", "./<name>": "./<name>/index.mjs" }`

4. **sideEffects 精确化**
   ```json
   "sideEffects": ["**/style/index.{js,ts}", "*.vue", "*.css", "*.less"]
   ```

**验证**：

## 假设与决策

### 假设
1. 当前项目无外部消费者依赖 CJS/UMD（ESM-only 不会造成破坏性影响）
2. `@ant-design/icons-vue` 可继续作为 `@xiaoye-ui/icons` 的底层依赖（方案 A）
3. 文档站的 less 样式可暂时保留（Nuxt 支持 less），后续再评估迁移到 cssinjs
4. `strictNullChecks` 开启可能需要修复大量类型错误，列为阶段 7 的可选子任务

### 决策
1. **ESM-only**：不产 CJS/UMD，CDN 用户改用 esm.sh
2. **monorepo 完整对齐**：9 个包全建，包括当前不需要的 nuxt-module/vite-plugin/mcp
3. **文档站迁移 Nuxt**：获得 SSR/SEO，但改动大
4. **icons 方案 A**：薄封装 `@ant-design/icons-vue`，不逐个迁移图标
5. **构建工具**：主库用 Vite 库模式，工具包用 tsup，nuxt-module 用 @nuxt/module-builder

### 风险与回滚
- **高风险阶段**：阶段 2（主库迁移）、阶段 3（构建链）、阶段 5（Nuxt 迁移）
- **回滚策略**：每个阶段独立 commit，如遇问题可 `git revert` 回退到上一阶段
- **验证关卡**：每个阶段结束必须通过 typecheck + test + build，不通过不进入下一阶段
